# DawaCore Client Upgrade Standard

هذه الوثيقة عقد إلزامي لأي تحديث دوري يُسلَّم لعميل DawaCore.

## 1. أنواع الحزم

- `UPGRADE`: يحافظ على البيانات ويطبق migrations إضافية فقط.
- `CLEAN_REBUILD`: يمسح بيانات الأعمال بعد نسخة احتياطية وتأكيد حرفي مستقل.
- لا يجوز تحويل حزمة Upgrade إلى Clean Rebuild تلقائيًا.

## 2. الفحص الأولي الإلزامي

- اكتشاف مسار التطبيق وملف `.env` دون طباعة الأسرار.
- اكتشاف Node وPostgreSQL من Runtime المضمّن أو المسارات القياسية.
- التحقق من خدمة PostgreSQL والمنفذ والاتصال.
- قراءة إصدار التطبيق وحالة `_prisma_migrations` والجداول المطلوبة.
- رفض الحزمة قبل إيقاف النظام إذا كانت النسخة الأساسية غير متوافقة.

## 3. التسجيل

- كل حزمة تكتب سجلًا دائمًا داخل `logs` منذ أول سطر.
- السجل يحتوي المرحلة، الوقت، الإصدارات، المسارات، exit code، ونتيجة الفحص الصحي.
- يمنع تسجيل كلمات المرور، `DATABASE_URL` الكامل، JWT، أو مفاتيح الترخيص.

## 4. النسخ الاحتياطي

- لا تعديل على قاعدة العميل قبل نجاح `pg_dump` والتحقق أن الملف غير فارغ.
- يسجل المسار وSHA-256 في تقرير التحديث.
- الاستعادة لا تتم تلقائيًا إلا ضمن إجراء استرداد مستقل ومختبر.

## 5. التطبيق والرجوع

- إيقاف الخدمة بعد الفحص والنسخة الاحتياطية فقط.
- migrations مرتبة، idempotent، ومختبرة على قاعدة مؤقتة مماثلة.
- لا تنسخ ملفات التطبيق إذا فشل ترحيل القاعدة.
- عند فشل ما قبل تغيير القاعدة يعاد تشغيل التطبيق السابق تلقائيًا.
- حفظ نسخة من ملفات التطبيق السابقة قبل الاستبدال.

## 6. التحقق النهائي

- تشغيل الخدمة وفحص HTTP health endpoint.
- فحص schema والمigrations المطلوبة.
- اختبار دخول، بيع، وردية، شراء، مصروف، ونسخة احتياطية على قاعدة قبول منفصلة قبل إصدار الحزمة.
- إنشاء `upgrade-report.json` بنتيجة `SUCCESS` أو `FAILED` في كل الحالات.

## 7. هوية الحزمة

- اسم فريد يتضمن الإصدار والتاريخ؛ لا يعاد استخدام اسم ZIP قديم.
- `manifest.json` وبصمة SHA-256 لكل ملف وبصمة للحزمة.
- الحزمة لا تحتوي `.env` أو `license.key` أو بيانات عميل.
